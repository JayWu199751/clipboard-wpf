# WPF 重写性能对比报告（旧 Tauri 版 vs 新 WPF 版）

日期：2026-10-04。机器：Windows 11 Pro，2560×1600 @175% 单显示器。
数据集：两代共用固定基准存档（200 条 = 192 文字 + 8 图含 1 张 4000×3000 大图 + 5 置顶，
`docs/acceptance/perf/make-dataset.ps1` 构造），每轮运行前恢复基准态。
方法：进程树（主进程 + 全部子进程）500ms 采样，场景时间轴 = 冷启动 0–35s → 空闲停靠 35–60s →
呼出序列 60–98s（首次 + 5 次重复 toggle，SendKeys 注入 Ctrl+Shift+V，间隔 6s）。
两代严格串行、每轮后零残留确认（采样循环见 `sample-round.ps1`，总编排 `run-all.ps1`，
原始 CSV 与三轮中位见 `perf-results/`）。

## 口径声明（重要）

- **旧版为 Tauri debug 构建**（asInvoker）：正式 release 构建带 requireAdministrator 清单，
  本会话无法静默提权启动（schtasks/reg 被代理沙箱禁用；本机 UAC 静默策略虽允许直启提权产物，
  但两代同完整性对比口径优先）。debug 未优化 → 旧版读数**偏高**。
- **新版为 Release 自包含发布构建的 asInvoker 清单变体**（`-p:ApplicationManifest=app.manifest`，
  代码与正式发布完全一致，仅清单差异）。
- 提权 release 对 release 的正式口径列为**待用户执行项**（用安装包 + 计划任务静默通道即可复跑同脚本）。
- **实测数字不构成节省宣称**；正式内存门槛（预算冻结）**留待用户按本报告拍板**（02-spec/03 既定顺序）。
- 工具限制：GDI 对象数无法采样（安全策略禁运行时编译 P/Invoke）；托管堆未单独采样
  （外部进程读托管堆需 diagnostic 会话，与采样器串行注入复杂度高——Private Bytes 已含托管堆）；
  图片缓存为 WPF 侧 ThumbnailCache 设计上限（≤32 张 / ≤24 MiB 解码像素），运行时曲线未单独导出。

## 定性结论（待用户拍板前不作为宣称）

1. **进程形态**：旧版 5 进程（exe + WebView2 子进程 ×4）vs 新版 1 进程——结构性简化。
2. **Private Bytes 持平**（冷启动/空闲段）：.NET 自包含运行时的私有内存与 WebView2 子进程树相当，
   呼出活动期新版因缩略图缓存上浮 ~11MB（上限 24MiB）——**本项目动机中的「降低常驻内存」
   在 Private Bytes 口径下未观测到显著差异**（待提权 release 口径复跑确认）。
3. **工作集/句柄/CPU 显著下降**（−43~−49% / −36% / −40~−80%）；旧版为 debug 口径，读数偏高侧属旧版。
4. 操作耗时：呼出/滚动/复制的端到端延迟未做外部秒表级测量——WPF 侧已有 E2eT09
   4K 206 条滚动 139.9ms/批、P4 高频导航 8.8–21.8ms/步参照；旧版无同口径数据，
   留待用户实测对比。
