# ADR-0001：发布形态与最低系统

日期：2026-10-03。状态：已接受（用户拍板）。

## 背景

资料包 `02-spec/03-WPF架构与性能计划.md` 把四项发布决策列为仅用户能定的问题：
Windows 最低支持版本、框架依赖 vs 自包含、字体分发、升级安装身份。
2026-10-03 用户逐项确认（第 4 项明确未取「保持原产品身份」建议）。

## 决策

1. **最低系统：Windows 10 22H2 及 Windows 11**。测试矩阵不覆盖 Win10 1607–21H2；
   PerMonitorV2、`SystemUsesLightTheme` 等暗色注册表键、Shell API 均按可用处理，不做分版本降级分支。
2. **发布：自包含**。NSIS 安装包携带 .NET 10 桌面运行时，用户机器无需预装；
   代价是安装包约 70–100MB。开发/CI 构建仍用本机 SDK。
3. **字体：普通界面文字内置思源黑体，等宽字体不随包分发**（2026-10-08 用户确认修订）。
   普通文字使用 Adobe Source Han Sans 2.005R 的简体中文子集静态 OTF（Source Han Sans CN，Regular 与 Medium），
   作为 WPF Resource 随程序集分发，缺字回退 Segoe UI→系统；面板和托盘菜单共用该字体。
   等宽区域保留 mono=JetBrains Mono→Cascadia Code→Consolas。
   字体原文件不修改，SIL Open Font License 1.1 的版权与许可文本随构建和发布输出携带，详见
   [字体来源说明](../../ClipboardTool.Presentation.Wpf/Assets/Fonts/SourceHanSans/README.md)。
4. **安装身份：新产品身份**。新版 NSIS 采用独立 productName/GUID，与旧 Tauri 版互不覆盖。

## 后果

- 决策 4 意味着「升级」分两件事：旧→新是一次**切换**（备份存档→退出并卸载旧版→安装新版→验证，
  两代不得同时运行，否则争抢呼出键、共写 `%APPDATA%\ClipboardTool`）；新版自身的后续版本升级
  按新身份的 NSIS 升级逻辑验收（F38 的「升级重启」对新版产物成立，不再对旧版产物成立）。
- 自包含发布使「目标机无 .NET 运行时」不再是失败路径；运行时体积计入安装包验收记录。
- Win10 22H2 主流支持已结束，若用户群要求更宽支持需修订本 ADR 并重开测试矩阵。
- 普通文字按用户确认改为思源黑体，不再要求与旧版字体一致。保留原有字号、字重、行轨和留白；
  字体字面与度量变化后，仍需核验截断、换行和密度。两份内置字体增加发布程序集体积。
