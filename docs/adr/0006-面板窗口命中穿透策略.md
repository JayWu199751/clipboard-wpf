# ADR-0006：面板窗口命中穿透策略

日期：2026-10-03。状态：已接受（依据 P5 试验证据）。

## 背景

36 DIP 圆角外壳要求：弧外透明区鼠标穿透到下层窗口、弧内（搜索井、卡片、页脚）正常交互；
不能整窗 ClickThrough（搜索不可点）、不能全窗永久穿透。浏览态（WS_EX_NOACTIVATE，ADR-0002）
与输入态（激活）都要成立，且跨分数 DPI（100–175%）与多显示器负坐标屏。
WPF 能否等价 legacy（Tauri 透明窗 + CSS border-radius）的穿透行为是试验 P5；
证据见 [prototype/p5-rounded-hit-test/REPORT.md](../../prototype/p5-rounded-hit-test/REPORT.md)
（2026-10-03，Win11 26300 x64 真机 2560×1600 @175%，自动断言 16/17 通过、唯一未过为设计中的归因负发现，
几何单测 19/19 全绿）。

## 决策

1. **穿透机制 = 分层窗口逐像素 alpha**：`PanelWindow` 保持无边框 + `AllowsTransparency=True`
   （`WindowStyle=None`、`Background=Transparent`），弧外 0 alpha 区由系统逐像素命中测试天然穿透，
   跨线程/跨进程成立，浏览态与输入态行为一致（试验归因矩阵：仅 alpha 时角外点击落到下层窗口，
   前台移交可观测）。这与 legacy 透明窗机制同构。
2. **命中几何 = WM_NCHITTEST 钩子 + 纯函数**：窗口钩子按 `CornerHitGeometry` 纯函数判定
   （原型即蓝本）：lParam 屏幕**有符号** 16 位解析（负坐标屏）→ 减 `GetWindowRect` 原点得本地物理坐标 →
   角部方带外必命中、角部按到弧心的欧氏距离判定（恰在弧上归弧内）；radius 物理值 = 36 DIP ×
   `VisualTreeHelper.GetDpi` **每窗口实时值**（PerMonitorV2，`DpiChanged` 时更新缓存，禁用系统级常量）。
   弧内返回 HTCLIENT、弧外返回 HTTRANSPARENT。与视觉弧共用同一 radius 常量，严格同源。
3. **不用整窗穿透**：禁止对 `PanelWindow` 常设 `WS_EX_TRANSPARENT`（搜索井/卡片/页脚必须可点）；
   动态开关式整窗穿透也不采用——弧级几何已由 1+2 覆盖。
4. **HTTRANSPARENT 语义边界（负发现钉死）**：其对**真实鼠标输入只在同一线程队列内向下转发**，
   跨线程时点击被系统丢弃（试验 C3：角部不透明后点击丢失、前台变 NULL）；`WindowFromPoint`
   查询会尊重它，不能以查询结果推断真实点击路由。因此未来若出现「像素不透明但需穿透」的区域
   （如不透明阴影/遮罩），HTTRANSPARENT 不解决问题，需另行评估 WS_EX_TRANSPARENT 动态开关并出新 ADR。

## 后果

- 11 票（T07）的 `PanelWindow` 按决策 1–3 接入：允许透明壳 + WM_NCHITTEST 钩子 + 每窗口实时 DPI；
  F17 验收矩阵「角外点击下层」的预演证据即 P5 判据①（浏览态与输入态双证据）。
- 抗锯齿 fringe（alpha 1–254 的边缘像素）点击被丢弃而非落入面板：浏览态无误交互，可接受
  （带宽 1–2 物理像素，与描边视觉重合）。
- 真机人工项：100/125/150% 系统档位运行时行为、真实多显示器负坐标屏、物理鼠标/触屏点击
  （见 REPORT 未覆盖项）；数学口径已由四档参数化单测钉死。
- `CornerHitGeometry` 移植进主工程时归 Domain.Geometry（纯函数、零框架依赖，19 例单测随迁）。
