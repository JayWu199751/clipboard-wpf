# ADR-0004：模式执行线程与粘贴链路线程模型

日期：2026-10-03。状态：已接受（T02 内定案，回应工单「模式单一串行写入者 = UI Dispatcher 还是专用 executor」）。

## 背景

复制并粘贴链路（02-spec/02 §2）包含恢复焦点+注入（AttachThreadInput、SetForegroundWindow、
SendInput、48ms×4 级回读等待、60ms 重试），是全应用唯一的长阻塞平台操作。它由浏览态的全局 Enter
与卡片双击触发，而失败路径要求面板保持可见并渲染错误文案——若链路占住 UI 泵，等待期间面板冻结、
错误提示无法及时渲染。legacy 用专用模式执行线程承载状态机（legacy ADR-0006）。

## 决策

1. **模式单一串行写入者 = 专用执行线程**（`Application.ModeExecutor`：单后台线程 + 有序队列，
   具名意图串行执行）。UI 线程只发具名意图、渲染事实（结果契约 message / 条目变更事件）。
2. **粘贴链路整体跑在执行线程上**（`PasteService` 实现六步端口）；恢复/注入的非泵线程模型由
   P2 试验证实可行（探针即非泵线程，连续三轮全绿），legacy 同构。
3. **UI 相关步骤经 Dispatcher 归队**：`hide_after_paste`（停靠）与焦点错误/结果提示是单向通知，
   不回等执行结果。
4. **呼出/停靠的几何落地暂留 UI 线程**（T01 既有实现：非阻塞、毫秒级、依赖 WPF 控件树）；
   T04/T05 键位与模式重构时随状态机迁入执行线程——意图入口（Post）已就位，迁移是搬移不是重设计。
5. 焦点快照在**呼出处理线程**（WM_HOTKEY 到达处）捕获后交给链路（F13/F14）；停靠/再呼出即失效。

## 后果

- UI 线程永不执行 AttachThreadInput/SendInput/OpenClipboard 重试——失败路径面板渲染不被阻塞。
- 执行线程上的意图异常不得终止线程（ModeExecutor 捕获后丢弃；失败结果由意图自身经结果契约回报）。
- 领域 PasteChain 保持同步签名：异步边界属于适配层（legacy 把 await 藏在 PastePort 两个方法的动机
  在 C# 下由 ModeExecutor + Dispatcher 归队等价实现，领域层不再携带 Task）。
- 搜索/备注输入态的键位让位（F18–F21）落地时沿用本决策：输入态切换意图进执行线程。
