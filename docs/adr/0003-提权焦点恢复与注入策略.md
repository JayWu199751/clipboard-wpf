# ADR-0003：提权焦点恢复与注入策略

日期：2026-10-03。状态：已接受（依据 P2 试验证据）。

## 背景

粘贴链路（02-spec/02 §2，legacy ADR-0005 的顺序契约）的最后一步是「恢复原窗口焦点并注入 Ctrl+V」。
发布形态是整工具常驻提权（ADR-0001），因此恢复/注入发生在高完整性进程侧，目标可能是普通或
管理员窗口。WPF 能否等价复刻 legacy `focus_paste.rs` 并满足安全契约（失效目标必须取消注入、
恢复/注入失败分开报、SetForegroundWindow 返回值不作数、UIPI 阻断不可从 GetLastError 判断），
是 T02 的阻塞试验 P2；证据见
[prototype/p2-elevated-focus/REPORT.md](../../prototype/p2-elevated-focus/REPORT.md)
（2026-10-03，Win11 26300 x64，连续两轮 6/6 门禁全过 + 负控证实）。

## 决策

1. **算法整体沿用 legacy `focus_paste.rs` 的 C# 移植**（`prototype/p2-elevated-focus/FocusRestore.cs` 即蓝本）：
   快速路径（目标仍前台且焦点未变→零操作）、最小化先恢复、AttachThreadInput 级联 + 对称解绑、
   有限激活级联（ASFW → 无害 Alt → SwitchToThisWindow → ShowWindowAsync+SetWindowPos）、
   每步以 4ms 步进回读前台归属（预算 48ms）、失败重试一轮（60ms 间隔）。
2. **快照四元组（顶层 HWND/焦点 HWND/PID/TID）整组校验**：HWND 可复用，PID/TID 不匹配即拒绝，
   拒绝路径零 SendInput（P2 判据 3 证实拒绝在 restore 阶段发生且计数为 0）。
3. **注入成败以回读为准，不信 SendInput 返回值**：P2 负控实测——medium 进程向 high 前台注入时
   SendInput 返回 4/4 但内容被 UIPI 静默过滤。注入数量校验（返回 4）只是前置条件；
   用户可见的成功状态只能来自目标侧回读（02-spec/02 §2 的结果契约）。
4. **失败分开报且不降级**：`{ stage: restore|paste, reason }` 契约与用户文案同源
   （`无法恢复原输入框…` / `复制已写入剪贴板，但无法粘贴回原输入框…`）；restore 失败绝不把内容
   注入「当前前台」（P2 判据 5 证据：失败时前台与牺牲窗均未受扰）。
5. **恢复目标必须是稳定运行态**：探针期间观察到「刚拉起即激活」的子进程 UI 线程可复现冻结
   （激活失败、WM_CLOSE 不达）；正式实现不迁移此问题场景（目标是用户正在使用的窗口），但粘贴链路
   对激活失败保留重试与明确报错。

## 后果

- T02 的 `Infrastructure.Windows.FocusAdapter` 按本 ADR + `FocusRestore.cs` 实现；
  `P2_FORCE_PASTE_FAIL` 环境变量等探针设施不得带入正式实现。
- 提权目标粘贴的真机验收项（T08/T09）以 P2 判据表为预演证据，验收时只需确认
  真实键盘路径与多显示器场景（本试验未覆盖项）。
- UIPI 低→高方向的行为由负控钉住：若未来用户报告「管理员窗口粘贴失败」，先查工具是否提权，
  而不是怀疑注入算法。
