你要把 Windows 剪贴板历史工具 ClipboardTool 从 Tauri 2 + React 19 + Rust 重写为 **C# + 原生 WPF**。主要动机是降低常驻内存，同时保留现有所有功能、交互细节、旧存档和 Windows 平台行为。此次需要可运行、可测试、可安装的真实桌面工具。

## 工作原则

- 全程中文沟通、注释、文档与提交信息；术语沿用资料包中的 `04-reference/legacy/CONTEXT.md`。
- 先检查 `git status`。有未提交的已有工作时先读差异，再按已有授权提交可回退基线；新建的空仓库先建立基线。
- 在新仓库实现 WPF；`04-reference/legacy/` 是只读事实源，不修改它，也不继续开发旧 Tauri 工程。
- 主界面全部用 XAML / WPF 控件绘制，不嵌入 WebView2、Chromium、Electron 或 HTML。资料包的 HTML 只用于视觉与交互参考。
- 优先保持功能与行为等价；必要的平台适配与资源优化记录为决策。不能因「更省内存」静默删功能、缩短撤销窗口、限制图片尺寸或损坏透明通道。
- 判定进入可脱离 WPF/Win32 测试的领域模块；效果由应用编排与基础设施适配器执行。通过小接口注入时间、ID、文件、剪贴板、热键、焦点与窗口端口。
- 阶段可以跨会话，但每个 ticket 必须自包含。以验收证据标记完成；未测的真机行为明确写「待验证」。

## 目标实现与硬契约

默认采用受支持的 .NET LTS + WPF，先核验 SDK；2026-10-03 的资料建议 .NET 10 LTS，目标 `net10.0-windows`、x64。依赖选型以当前官方文档为准，锁定版本；本包不承诺目标机已经有 .NET SDK。

至少划分 Domain、Application、Infrastructure.Windows、Presentation.Wpf、Tests；模块具体数量可按复杂度调整。模式只有一个串行写入者；UI Dispatcher 不等待持锁的模式任务，模式也不在持锁时同步等待 UI。全局热键必须由拥有目标 HWND/消息队列的线程注册，依据系统返回维护唯一的已生效键集合。UI 状态不充当系统事实。

以下五组行为是重写成败的核心，详细值只在规格中维护：

- 历史：文字/图片、来源应用、按内容判定身份、置顶块/普通块、最近使用落位、200 条上限与置顶裁剪规则、备注归一化、PNG 保存/删除与旧档加载。
- 面板：不抢焦点的浏览态、搜索态、备注编辑态、捕获态；导航键让位与中文 IME；光标所在显示器居中、DIP 比例尺寸、圆角穿透、屏外停靠、呼出落地回读、任务栏与 Alt+Tab 排除。
- 复制并粘贴：按契约顺序取内容→写剪贴板→落位与基线同步→取焦点快照→恢复并注入→成功才停靠。失败文案统一、失败保持可见，目标失效时取消注入。
- 常驻：系统通知监听、占用重试、失败轮询兜底、自写去重；全局呼出与方向键重复；单实例、托盘、三态主题、常驻提权、计划任务静默启动与开机启动意图/事实、诊断轮转。
- 界面：尽量逐数值还原现有 HUD 的布局、密度、明暗、图标、三行文字、150 DIP 图片、备注零位移、自绘细滚动条、搜索高亮、页脚与 toast；键名提示来自真正键位注册表。

旧存档目录仍是 `%APPDATA%\ClipboardTool`。旧 JSON 键名、条目 id、时间单位、PNG 文件名保持可读可往返；加载来源与渲染投影分别建模。在迁移试验中用存档副本，禁止用用户真实档案跑清空/裁剪测试。正式切换提供备份、迁移报告和回退方法，原版与新版不要同时运行争抢呼出键或写同一存档。

## 性能与交付验收

先执行性能计划建立原版进程树基线，再对 WPF 发布构建以相同数据测冷启动、空闲停靠、首次呼出、重复呼出、大图滚动和连续复制。分别报告 Private Bytes、工作集、托管堆、CPU、句柄、GDI 对象、图片缓存与操作耗时。预算在性能文件中明确是初始目标；没有实测就不能说节省了多少。

图片完整内容只在磁盘和复制链路中按需读取；可视缩略图限尺寸解码，缓存有条数与字节双上限，离屏回收；列表 Recycling 虚拟化经过实际容器计数验证。禁止永久存全量 base64/原尺寸 Bitmap、每次变化全量重建图片列表、用持续强制 GC 或压工作集伪装优化。

每个 ticket 完成：相关自动测试全绿、`dotnet build -warnaserror` 零警告、真实变化同步文档、提交中文信息并给出证据。最终执行完整验收矩阵；人工步骤逐项标结果，不以纯单测替代管理员目标粘贴、开机启动、跨屏 DPI 或 NSIS 验证。

最终交付包含：完整源码与 solution、锁定的依赖/SDK、测试、构建运行说明、提权与 DPI 清单、NSIS 安装/卸载、旧档兼容样例、迁移回退说明、功能覆盖表、性能前后对比和未验证项。先把上述阅读与工作计划做具体，随后持续推进首个纵向 ticket，不停在泛泛的方案建议上。

# 存档与平台迁移契约

用户行为由 [功能清单](../02-spec/01-功能清单.md) 定义，本页只集中维护字段、时序与平台边界。事实源：`../04-reference/legacy/tauri/src-tauri/src/` 和 `legacy/docs/adr/`。

## 1. 旧存档格式

目录 `%APPDATA%\ClipboardTool`；历史 `clipboard-history.json` 是 **JSON 数组**，不是包一层 `{ entries: ... }`。不要把运行期 RendererEntry.dataUrl 当成历史存档字段。

```json
[
  {
    "id": "e2c9ad03-84bf-47b1-911a-0542b0f3a301",
    "type": "text",
    "text": "完整正文\n保留换行与空格",
    "createdAt": 1790992800000,
    "sourceApp": {
      "exePath": "C:\\Windows\\System32\\notepad.exe",
      "appName": "notepad",
      "windowTitle": "示例 - 记事本",
      "iconDataUrl": null
    },
    "pinned": false,
    "pinnedAt": 0,
    "note": "示例备注"
  },
  {
    "id": "1cc08a9e-8ec1-4f53-a6c2-a50a72eb5b20",
    "type": "image",
    "imagePath": "C:\\Users\\示例用户\\AppData\\Roaming\\ClipboardTool\\images\\1cc08a9e-8ec1-4f53-a6c2-a50a72eb5b20.png",
    "createdAt": 1790992810000,
    "sourceApp": null,
    "pinned": true,
    "pinnedAt": 1790992820000,
    "note": ""
  }
]
```

| 字段 | 类型与迁移规则 |
|---|---|
| id | 非空字符串；已有 id 原样保留，新 id UUID；PNG 真名 `<id>.png` |
| type | 精确 `text` / `image`；未知类型跳过该条 |
| text / imagePath | 对应类型必需的内容/磁盘路径；序列化互斥的可选字段不随意填 null；imagePath 兼容现有绝对路径，迁移测试须有真实测试 PNG |
| createdAt / pinnedAt | Unix epoch **毫秒整数**，不是 .NET ticks/秒/本地日期字符串；缺省 0；取消置顶当前保留 pinnedAt |
| sourceApp | 可为 null；对象四键默认空字符串/图标 null；保持旧图标可读，不将其误画为现有卡片 UI |
| pinned | bool，缺省 false；加载后重建置顶块 |
| note | 缺省空串，保存去首尾空白并按 Unicode 字符截断 200 |

```json
{"autoStart":false,"shortcut":"Control+Shift+V","theme":"system"}
```

设置持久化键只有 autoStart / shortcut / theme；写出 camelCase，读取兼容 auto_start。两者都有时以有效的 autoStart 布尔值优先；字段类型坏不能连带丢其他合法字段。theme 仅小写 light/dark/system，缺失/非法回 system；shortcut 缺失/空串回默认，不把合法自定义字符串悄悄重命名。

**字符计数兼容细节**：旧 UI 的 maxLength/字数是 JavaScript UTF-16 单位，旧存储 `chars().take(200)` 是 Unicode 标量；二者并非完全相同。WPF 持久化归一化使用 `EnumerateRunes()` 保留存储语义，编辑器明确采用与旧 UI 相同的 200 UTF-16 单位上限或记录经用户确定的调整；不按 grapheme 自创规则，测试 emoji/代理对边界避免损坏 UTF-16。

加载整体坏档按旧行为回空历史/默认设置，但正式迁移**先备份坏档**再写；不要用空列表覆盖唯一原件。新实现可以增加原子写入与失败提示，这是可靠性改进建议，需测试 `.tmp` 写入、替换失败及重启恢复。避免修改已写入用户磁盘的键名。备份与迁移日志放独立路径，不把控制字段塞进旧数组。

切换：退出旧应用→复制存档备份→用副本验证新版读/写/重启→再切正式存档→核对条数、PNG、置顶、备注与设置；回退：退出新版→还原原版可读备份→恢复指向旧 exe 的任务与快捷方式。不能两个实现同时写同目录。

## 2. 粘贴链路顺序

唯一服务返回 `{ ok, message }`；Enter 与双击调用同一入口，错误阶段与用户提示同源。

```text
content_of(id)
  → write_clipboard(content)
  → settle_after_copy(id) [提升、落盘、通知、同步轮询基线]
  → focus_target() [本次呼出的焦点快照]
  → restore_and_paste(target)
  → hide_after_paste() [只在成功时，不再归还焦点]
```

| 结果 | 文案/效果 |
|---|---|
| 条目丢失/内容不可用/写失败 | `条目不存在或内容已不可用。`；后续步骤不执行 |
| 无快照或恢复失败（restore） | `无法恢复原输入框，已取消本次粘贴，避免写入错误窗口。`；已完成落位，保持可见，无注入 |
| 已恢复但注入失败（paste） | `复制已写入剪贴板，但无法粘贴回原输入框，请重试。`；保持可见 |
| 成功 | `已复制并粘贴`；停靠且不再次恢复焦点 |

旧 Win32 快照保存顶层 HWND / focus HWND / PID / TID；PID/TID 校验防 HWND 复用。快速路径在目标仍是前台且焦点未变时直接通过；最小化恢复、AttachThreadInput 对称解绑、有限激活级联与注入数量校验参考 `focus_paste.rs`。WPF 不直接照搬每个旧退让 API，必须验证等价安全结果；调用 SetForegroundWindow 返回值不是唯一事实，回读目标归属与控件。失败不能改对「当前前台随便粘贴」的降级。

写图片交付位图数据；保证透明通道及与截图/Office 等目标程序兼容，不把路径或仅自定义 PNG 格式当完整替代。发布进程提权是注入管理员目标的既定前提，UIPI 阻断未必能从 GetLastError 判断（官方资料见参考索引）。

## 3. 模式与线程

四态的目标键集合按 F18–F21；捕获态临时解除所有全局键，浏览态不可激活，搜索/备注可聚焦。停靠和呼出是状态机操作，外部只发具名意图。输入态退出先完成编辑/让位/归还原快照再恢复浏览键，不让退出动作成为粘贴 Enter。

旧死锁：全局热键插件内部投递 UI 并阻塞，主线程又等待模式锁。WPF 不沿用插件，但保持防线：

- 模式状态单一串行写入者（UI Dispatcher 或专用 executor，采用哪种进 ADR）；外部回调非阻塞投递具名操作。
- Win32 RegisterHotKey 对 HWND 所属线程有约束；如果用独立消息线程，窗口与 register/unregister 都在那里执行；不能直接从任意 worker 调 UI HWND 的注册。
- UI 与模式之间使用异步消息/回执；UI 不用 `.Result/.Wait()` 等模式，模式不持历史锁同步 Invoke UI；历史锁与模式不交叉。
- 已生效键集合由执行系统注册者维护，注册失败不上账；期望集合是推导结果，不是事实副本。
- 剪贴板独占读取在有消息循环的专用 STA 出口串行执行；取原始字节后立即释放，CPU 解码可放后台。WPF DependencyObject 只在归属 Dispatcher 操作，跨线程 BitmapSource 先 Freeze。
- 钩子回调只记录时间/坐标/键事件并投递；绝不在那里解码、写盘、同步等待 UI 或跑长重试。
- 图片读取/保存与历史快照的时序需保证通知不越过提交；复制基线同步与监听之间要串行协调，不能因取消锁而引入重复记录。

## 4. 剪贴板边界

保留「可信空内容」「占用读不可信」「有可记录内容」「写盘欠重试」的明确结果类型，避免用 null 混淆。读取开始先取序列号；欠重试时不能因序列号没动跳过。启动预设基线、自己写入同步基线、图片优先与文字基线跟随参考原版 9 个 poll_baseline 测试。

事件源成功后仅按通知/欠重试读；失败才 600ms 轮询。消息通知不保证源已释放剪贴板，也不保证无人争抢；旧 DIB 打开预算 8×10ms，事件欠账 50ms 重试。可调整内部策略但需有限回退、日志、及时新变化处理，不能永久忙循环。序列号确认的是触发读取的值，读取中再变化需要后续再次处理。

DIB 解析只接受验证过的头/格式，校验掩码、跨度、像素起点、数据长度和整数溢出；V4/V5 掩码在头内不能重复加 12 字节；alpha 与上下行序保留。PNG 编码器变化可能令旧 PNG 内容哈希不同：先用旧文件/相同像素回归去重，必要时记 ADR 引入向后兼容的规范化像素比较，仍维持「身份只看内容」，不能直接改键为来源+内容。

## 5. 窗口与系统事实

尺寸按完整显示器物理高 ÷ 缩放得到 DIP 高再乘 7/8 四舍五入，宽为高/2 四舍五入；位置按扣除任务栏的工作区居中。不要把工作区高当作尺寸输入，混 DPI 的全局坐标不能用一个固定 scale 换算所有屏。

旧停靠是工作区右缘外 20 DIP（y 在工作区顶部，无显示器时 -10000,0）。WPF 可优化停靠实现但必须保留复用生命周期、呼出延迟与焦点行为，改变可见性策略需 ADR 和真机验证。回读 IsWindowVisible/矩形/扩展样式并区分 Hidden/Moved/Offscreen；修复重设、显形或主屏兜底后再回读。旧几何容差 2 DIP。不要靠「API 成功」宣称呼出落地。

几何意图代次防迟到效果；启动热身与呼出同序，呼出请求发生后不再执行旧热身停靠。点击时间以钩子时刻判断，早于呼出不收。透明圆角命中几何由当前 radius 决定，浏览/输入态要分别验 WM_NCHITTEST 与命中/焦点切换，不只给窗口设置 ClickThrough。

无任务栏/Alt+Tab：WPF ShowInTaskbar=false 与工具窗口样式（WS_EX_TOOLWINDOW、清 APPWINDOW）应在窗口创建/显示后的 OS 真值验证，尤其登录、Explorer 重启、所有输入态。禁止让全窗永久透明穿透，以免搜索不可点。

## 6. 启动、主题、日志

常驻提权方案来自 ADR-0001/0002，计划任务名 ClipboardToolElevated、最高权限、登录触发器由 autoStart 控制。关闭开机启动移触发器，不删除静默按需通道。升级时更新任务 exe 路径；卸载移除任务/快捷方式，用户存档默认保留并明确说明。后两项是新版交付验收要求，不声称现有 NSIS 已逐项验证。

单实例 IPC 不必模仿 Tauri 协议；建议 mutex + named pipe，并处理提权与普通完整性通信权限、初始化未就绪、请求仅接受本用户的合法呼出动作。两种完整性下的 mutex 命名/ACL 需要实际验证。

主题偏好与生效主题/任务栏主题分别建模。WPF ThemeService 单一权威协调设置、ResourceDictionary 与菜单；UI 初始值/事件/异步读取顺序有代次，切换失败可重试。跟随系统看应用模式、托盘看任务栏模式。WPF 不需要模拟 prefers-color-scheme 或原 Tauri 事件名。

diag.log 保留两档与 pid，超过 512KB 轮转 diag.log.1；在新平台记录 start/hotkey_register/summon-req/summon-run/summon-landed/hide/exit-requested/exit 与模式执行/窗口落地失败。崩溃记录到 panic.log；默认日志不包含剪贴板正文与完整截图。对日志资源做关闭与轮转竞争处理。

## 7. 旧 IPC 如何迁移

WPF 不需要 Rust→React IPC；将旧入口映射为应用服务，便于追踪完整性：clipboard_get→HistoryService 只读；clipboard_copy→PasteService；clipboard_remove/pin/note_set→HistoryService；note_end_edit/search_activate/composing/shortcut_try/cancel/window_hide→PanelCoordinator；theme_get/set→ThemeService；window_set_ignore_mouse→PanelWindowAdapter 命中策略。旧 clipboard:updated/panel:key/panel:shown/focus-error/theme:changed/capture-start/end 转为类型化通知或 ViewModel 状态变化。

清空历史只有托盘用户入口，备注编辑由 B 键触发；不为重现已经删除的 IPC 新增多余公开 API。功能可以内部统一应用服务，但不把所有服务开放给 UI 任意调用。

# WPF 目标架构与性能计划

本页是实现建议及初始预算，区别于 [当前功能](../02-spec/01-功能清单.md) 与 [硬契约](../02-spec/02-存档与平台契约.md)。尚未生成 WPF 工程，所有预算均未实测。官方依据见 [参考索引](../04-reference/README.md)。

## 建议技术基线

2026-10-03 核验微软支持政策，.NET 10 为 LTS，建议 C# + `net10.0-windows` WPF、x64。开始实现时检查 SDK/Windows 支持范围并锁 `global.json` 与依赖；当前资料制作环境未发现 dotnet 命令，不据此安装 SDK。MVVM 可以简洁手写或使用少量 CommunityToolkit.Mvvm，是否引入由实际复杂度决定。

生产 UI 仅 XAML；托盘可用 WinForms NotifyIcon + 精确 HICON 或直接 Shell_NotifyIcon，小接口隔离；不要仅为菜单引一整套主题控件库。P/Invoke 用 LibraryImport/明确结构布局与所有权，UI 不直接散落 Win32。JSON 用 System.Text.Json 配字段显式契约；PNG 编解码先以 WIC/WPF 能力做 DIB/透明与哈希兼容试验，必要依赖有明确原因。

## 建议模块

| 项目/模块 | 对外职责与边界 |
|---|---|
| ClipboardTool.Domain | History、PanelModes、PendingDeletion、Search、HotkeyPlan、PasteChain、Geometry、Settings 纯规则；普通 POCO/不可变值；不依赖 WPF/WinForms/PInvoke |
| ClipboardTool.Application | PanelCoordinator、HistoryService、PasteService、ThemeService、StartupService；串行命令、结果、事务与事件；必需端口构造注入 |
| ClipboardTool.Infrastructure.Windows | ClipboardMessageSource、ClipboardReader/Writer、DibDecoder、FocusAdapter、HotkeyExecutor、MouseHook、SingleInstance、ScheduledTask、JsonStore、Diagnostics、ThumbnailCache |
| ClipboardTool.Presentation.Wpf | App 启动与资源、PanelWindow、PanelViewModel、SearchHeader、文字/图片 DataTemplate、InlineNote、Footer、Toast、CaptureOverlay、主题字典与 AutomationPeer |
| ClipboardTool.Tests | 领域协议、旧档往返、平台字节与接口集成测试；独立可选的 Windows 真机探针与 UI 验收 |

深模块只给具名操作，内部状态/缓存/模式不外泄；避免 ViewModel 成为第二份 HistoryStore。UI 列表保留条目元数据投影，完整正文按需求引用或磁盘读，缩略图是资源句柄不是巨大的 base64。历史落位变化发布 id/差量或轻量快照，不反复复制全部图片数据。

ViewModel 临时态：selectedId、query、searchActive、noteDraft、captureStatus、focusError、toast。持久领域态：History/Settings。系统事实：已生效键集合、当前前台/焦点、窗口真矩形、任务存在/触发器、主题注册表。每类只有一处真源；输入与取消操作不提前覆盖已提交字段。

## 内存设计

1. ListBox/ItemsControl 使用 VirtualizingStackPanel 与 Recycling；变高图片卡的滚动测量、选中项可见、返回顶部、插入置顶时保留行为。不能外包无界 ScrollViewer、CanContentScroll=false 或直接添加容器令虚拟化失效。验证实际 realized containers 接近可视数+有限缓存，不能只看 XAML 属性。
2. 元数据与缩略图分离。按可视区及少量预取队列加载，解码到实际缩略图物理像素（约 150 DIP 高 × DPI），复制才打开全尺寸原图。BitmapImage 用 OnLoad 关闭流、Freeze 跨线程；取消旧请求、校验 id/代次，防回收容器显示错图。
3. 缩略图缓存初始建议「至多 32 张且估算解码像素不超过 24 MiB」双上限 LRU；按 stride×height 计解码占用，附加对象开销另外观测。移除/裁剪/清空立即失效；停靠后允许回收不可见缩略图，原始 PNG 不常驻。缓存超大单项不永久持有。
4. 来源图标与 hash 缓存有界，避免每个窗口标题生成新图标副本；源 iconDataUrl 是旧档可读字段，不强迫运行期同时持字符串、PNG bytes、Bitmap 三份。
5. 长正文不在列表元素里构建全部 Run，仅三行可视投影；搜索匹配完整正文，120ms 防抖取消旧查询，查询与 highlighted spans 有界生命周期。不要静默截断保存正文以省内存。
6. 监听消息阻塞等待，无正常态高频轮询；未占用无 timer；方向键重复仅按住时运行。后台线程数与队列容量可观察且有退出协议，不复制旧版每条一次性线程布局。
7. PInvoke handles 用 SafeHandle 或明确 Dispose；HICON、HBITMAP、HGLOBAL 所有权、hook 委托寿命、事件解绑、CancellationTokenSource/timer、文件流都列清。SendInput/GetGUIThreadInfo 在 x64 结构布局正确。
8. UI 不每次呼出销毁/重建；窗口透明层/AllowsTransparency、阴影与大面积 Effect 的开销要测；先保持现有视觉与命中，后按证据选实现。不要用常驻 GC.Collect、EmptyWorkingSet 或最小化技巧美化数字。

微软区分 UI 虚拟化与数据虚拟化：前者不会自动丢掉全部绑定数据；图片缓存与原图按需加载是本项目另外承担的资源策略（[WPF 控件性能](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)）。

## 基线与初始预算

**先测旧版再冻结预算**。以下是讨论用目标，不是用户已拍板的承诺；如达不到，报告构成与优化证据，让用户按实际结果确认门槛。预算按发布 x64、无调试器、同机三次独立进程取中位数与范围。

| 场景 | 初始目标 |
|---|---|
| 空历史启动稳定后停靠 60s | Private Bytes ≤ 60 MiB；空闲 CPU 平均 ≤ 0.5%（记录逻辑核数量与口径） |
| 200 条文字（每条约 1KiB）停靠 | Private Bytes ≤ 80 MiB |
| 160 条文字 + 40 张 4K PNG、完整滚动后停靠 30s | Private Bytes ≤ 120 MiB，持有全尺寸原图数为 0；与旧进程树同场景比较 |
| 100 次呼出/停靠、200 次滚动/编辑/撤销 | 最后稳定 Private Bytes 较首轮稳定值增量 ≤ 10 MiB，句柄/GDI 无持续上升趋势 |
| 热呼出到首个可用帧 | p95 ≤ 100ms，首次单独报告；不含人为等待热键按下 |
| 普通文字复制通知到列表可见 | p95 ≤ 100ms；4K 截图单独测，不能因错误抹基线而「很快」 |
| 恢复焦点并注入 | 成功路径 p95 ≤ 150ms；目标失效及时失败且零误注入 |

上述任一预算受控于数据与字体/主题/DPI；无限长文本、大图解码时峰值另记，不以稳态上限限制用户有效内容。旧版占用需要包含 exe 和全部 WebView2 子进程，不能用一个旧主进程对比整个 WPF 进程。

测量时标记：构建提交/Release、Windows/.NET 版本、DPI/屏幕/CPU/RAM、数据条数/PNG 字节/尺寸、主题、提权、采样间隔、运行 1/2/3、操作序列。Private Bytes 与 Working Set 分开；GC.GetTotalMemory 不代表原生/图像占用，系统压工作集后观察 Private Bytes/资源数是否依然高。

优先记录 Win32 Process PrivateMemorySize64、WorkingSet64、HandleCount、CPU 时间差与 GetGuiResources；托管堆/GC 可用运行时计数器或 profiler 补充。发布模式可用开发诊断探针采样，避免生产永久加载 profiler。表格模板见 `05-validation/02-性能记录模板.md`。
