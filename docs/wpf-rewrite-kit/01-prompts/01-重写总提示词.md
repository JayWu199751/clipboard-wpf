# 直接复制到新项目的总提示词

下面正文可以完整复制。默认你已把整个资料包放在新仓库的 `docs/wpf-rewrite-kit/`。

---

你要把 Windows 剪贴板历史工具 ClipboardTool 从 Tauri 2 + React 19 + Rust 重写为 **C# + 原生 WPF**。主要动机是降低常驻内存，同时保留现有所有功能、交互细节、旧存档和 Windows 平台行为。此次需要可运行、可测试、可安装的真实桌面工具。

## 工作原则

- 全程中文沟通、注释、文档与提交信息；术语沿用资料包中的 `04-reference/legacy/CONTEXT.md`。
- 先检查 `git status`。有未提交的已有工作时先读差异，再按已有授权提交可回退基线；新建的空仓库先建立基线。
- 在新仓库实现 WPF；`04-reference/legacy/` 是只读事实源，不修改它，也不继续开发旧 Tauri 工程。
- 主界面全部用 XAML / WPF 控件绘制，不嵌入 WebView2、Chromium、Electron 或 HTML。资料包的 HTML 只用于视觉与交互参考。
- 优先保持功能与行为等价；必要的平台适配与资源优化记录为决策。不能因「更省内存」静默删功能、缩短撤销窗口、限制图片尺寸或损坏透明通道。
- 判定进入可脱离 WPF/Win32 测试的领域模块；效果由应用编排与基础设施适配器执行。通过小接口注入时间、ID、文件、剪贴板、热键、焦点与窗口端口。
- 阶段可以跨会话，但每个 ticket 必须自包含。以验收证据标记完成；未测的真机行为明确写「待验证」。

涉及领域、热键、焦点、监听、JSON 或启动时，按功能清单的源文件索引读取 `04-reference/legacy/tauri/src-tauri/src/` 的对应实现与测试；涉及界面则读取 `legacy/tauri/src/`。先区分**当前行为**、**WPF 实现建议**、**待决问题**和**已知待验证问题**。遇到资料冲突，以基准提交的当前源码与测试为准，记录差异，不照搬旧截图或旧迁移文档。

阅读完成后交付：F01–F48 的覆盖表、拟采用的模块边界、仅靠用户才能决定的问题、风险最高的可运行试验清单。能从源码确定的事实自行查，不让用户重新讲功能。

## 使用 Matt skills 推进

先调用 `ask-matt` 核对当前阶段合适的技能，并检查实际技能文件是否存在。在这台机器 Matt 技能位于 `C:\Users\10854\.agents\skills\`；在其他机器按安装目录发现，不能假设路径或技能已经安装。

1. 检查 `setup-matt-pocock-skills` 的前置条件；已有 tracker 与文档布局可复用。没有外部 tracker 时优先采用仓库内文件 ticket。创建远程 issue、PR 或发消息按用户授权执行。
2. 使用 `grill-with-docs` + `domain-modeling` 澄清待决问题，维护 `GLOSSARY.md` 与 ADR。用户已经选择 C# + WPF，当前完整功能都已提供，不反复质疑技术路线或重新访谈已知事实。
3. 高风险未知先 `prototype`：不抢焦点的浏览态与可输入模式切换、管理员目标的焦点恢复、DIBV5 透明截图、虚拟化中的变高卡片、跨 DPI 圆角穿透。逻辑/平台试验使用隔离数据；HTML 原型不能证明这些 Win32 行为。
4. 使用 `to-spec` 把已确定事实和决策合成可实现规格，再 `to-tickets` 拆为有阻塞边的纵向 ticket。每个 ticket 引用功能编号、契约与验收，不按「先做所有服务、最后才做 UI」横向拆分。
5. 默认每个 ticket 使用 `implement`，内部用 `tdd` 按一条行为红→绿推进，随后 `code-review` 同时审标准与规格。若用户选择整图并行实现，再用 `implement-spec` 按依赖前沿编排。
6. 跨目录或跨执行环境时用 `handoff` 保存可移交的事实与证据；阶段收工用 `retro` 提炼环境与检查规则。阶段提示词见 `01-prompts/02-Matt技能分阶段提示词.md`。

## 目标实现与硬契约

默认采用受支持的 .NET LTS + WPF，先核验 SDK；2026-10-03 的资料建议 .NET 10 LTS，目标 `net10.0-windows`、x64。依赖选型以当前官方文档为准，锁定版本；本包不承诺目标机已经有 .NET SDK。

至少划分 Domain、Application、Infrastructure.Windows、Presentation.Wpf、Tests；模块具体数量可按复杂度调整。模式只有一个串行写入者；UI Dispatcher 不等待持锁的模式任务，模式也不在持锁时同步等待 UI。全局热键必须由拥有目标 HWND/消息队列的线程注册，依据系统返回维护唯一的已生效键集合。UI 状态不充当系统事实。

以下五组行为是重写成败的核心，详细值只在规格中维护：

- 历史：文字/图片、来源应用、按内容判定身份、置顶块/普通块、最近使用落位、200 条上限与置顶裁剪规则、备注归一化、PNG 保存/删除与旧档加载。
- 面板：不抢焦点的浏览态、搜索态、备注编辑态、捕获态；导航键让位与中文 IME；光标所在显示器居中、DIP 比例尺寸、圆角穿透、屏外停靠、呼出落地回读、任务栏与 Alt+Tab 排除。
- 复制并粘贴：按契约顺序取内容→写剪贴板→落位与基线同步→取焦点快照→恢复并注入→成功才停靠。失败文案统一、失败保持可见，目标失效时取消注入。
- 常驻：系统通知监听、占用重试、失败轮询兜底、自写去重；全局呼出与方向键重复；单实例、托盘、三态主题、常驻提权、计划任务静默启动与开机启动意图/事实、诊断轮转。
- 界面：尽量逐数值还原现有 HUD 的布局、密度、明暗、图标、三行文字、150 DIP 图片、备注零位移、自绘细滚动条、搜索高亮、页脚与 toast；键名提示来自真正键位注册表。

旧存档目录仍是 `%APPDATA%\ClipboardTool`。旧 JSON 键名、条目 id、时间单位、PNG 文件名保持可读可往返；加载来源与渲染投影分别建模。在迁移试验中用存档副本，禁止用用户真实档案跑清空/裁剪测试。正式切换提供备份、迁移报告和回退方法，原版与新版不要同时运行争抢呼出键或写同一存档。

## 性能与交付验收

先执行性能计划建立原版进程树基线，再对 WPF 发布构建以相同数据测冷启动、空闲停靠、首次呼出、重复呼出、大图滚动和连续复制。分别报告 Private Bytes、工作集、托管堆、CPU、句柄、GDI 对象、图片缓存与操作耗时。预算在性能文件中明确是初始目标；没有实测就不能说节省了多少。

图片完整内容只在磁盘和复制链路中按需读取；可视缩略图限尺寸解码，缓存有条数与字节双上限，离屏回收；列表 Recycling 虚拟化经过实际容器计数验证。禁止永久存全量 base64/原尺寸 Bitmap、每次变化全量重建图片列表、用持续强制 GC 或压工作集伪装优化。

每个 ticket 完成：相关自动测试全绿、`dotnet build -warnaserror` 零警告、真实变化同步文档、提交中文信息并给出证据。最终执行完整验收矩阵；人工步骤逐项标结果，不以纯单测替代管理员目标粘贴、开机启动、跨屏 DPI 或 NSIS 验证。

最终交付包含：完整源码与 solution、锁定的依赖/SDK、测试、构建运行说明、提权与 DPI 清单、NSIS 安装/卸载、旧档兼容样例、迁移回退说明、功能覆盖表、性能前后对比和未验证项。先把上述阅读与工作计划做具体，随后持续推进首个纵向 ticket，不停在泛泛的方案建议上。
